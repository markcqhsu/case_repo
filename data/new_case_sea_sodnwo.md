## 案例標題
東南亞 SO/DN/WO 營運資料分析平台（SEA SODNWO）

## 案例摘要
把東南亞各子公司從 ERP 匯出的 SO（銷售訂單）、DN（送貨單）、WO（工單報工）Excel 報表，集中上傳到同一個網站平台，經過驗證後自動彙整成接單、出貨、生產的分析儀表板，讓東南亞總部與管理層可依國家、公司、據點逐層查看營運狀況；平台上每一個數字都能追溯回原始 Excel 的那一列，不使用任何假資料或估計值。

資料整合與分析、內部管理工具

## 問題背景
東南亞各國子公司的接單、出貨與生產報工資料都存在 ERP 中，要看整體營運狀況時，只能由各單位各自匯出 Excel，再人工彙整成報表。各國幣別不同（THB、VND、MYR、IDR、MMK、USD），同一張單重新匯出後也容易重複計算，管理層很難即時、一致地掌握全區、各國、各公司、各據點的接單金額、出貨進度與生產良率，更難回頭查證某個數字是從哪一份檔案、哪一列來的。

## 核心問題
如何把分散在各國、格式一致但分次匯出的 SO/DN/WO Excel 報表，安全地匯入同一個平台，自動去重、換算幣別，並依使用者權限提供從集團到單一據點的營運分析，同時確保每個數字都真實、可追溯。

## 解決方案
以 React Router（SSR）+ Cloudflare Workers + D1 + R2 建立一個網站平台：
- 管理者上傳 SO/DN/WO Excel 後，系統先「預覽驗證」（必填欄位、Loc ID 是否已登記、是否重複檔案、新增/修訂/未變更筆數），完全不寫入資料；全部通過後才「確認匯入」，任何一份檔案有問題整批都不寫入。
- 以 ERP 的 Line Rec Key 作為每筆明細的唯一識別，同一張單重新匯出時只會產生新版本，不會重複計算；原始 Excel 永久保存在 R2，每一筆明細都可以追溯回原始檔案的工作表與列號。
- 各國 SO 金額依該國本位幣，再以全站共用匯率換算成報表幣別，缺匯率時誠實標示「未計入」而不是補 0。
- 儀表板依「集團 → 國家 → 公司 → 據點」四層範圍切換，並依使用者被授權的國家／公司／據點過濾可見資料。

## 執行流程
- 與東南亞總部確認 SO/DN/WO 來源 Excel 的欄位格式與分析需求，建立 35 個據點的 Loc ID 登記表與國家／公司歸屬
- 設計資料模型：匯入批次、原始列快照、明細身分與修訂版本、共用匯率、帳號與三層權限
- 開發 Excel 解析與兩段式匯入流程（上傳預覽 → 確認匯入），含真實進度條與整批作廢功能
- 開發總覽、接單與出貨、工單生產、同期比較、區域／公司／據點分析與單據詳情等頁面
- 部署至 Cloudflare Workers，並以 GitHub Action 每日自動備份資料庫
- 依東南亞總部使用回饋持續調整圖表、幣別換算與公司組織歸屬

## 主要功能
- 高層總覽｜六張 KPI 卡（SO/DN 金額、單據數、良品量、不良率）附「較上期」成長徽章、接單／出貨趨勢圖、產品組合與各範圍比較、規則產生的本期重點
- 接單與出貨｜SO/DN 依產品分類拆分的數量與金額、客戶與產品排行、DN 幣別分佈、明細表格搜尋與分頁
- 工單生產｜報工工單數、良品／報廢量、不良率趨勢、依產品分類與機台 Top 20 的生產指標
- 同期比較｜本期 vs 去年同期的單據數、金額、生產量與客戶／分類比較，無去年資料時誠實顯示「無資料」
- 四層資料範圍導覽｜集團 → 國家 → 公司 → 據點逐層下鑽，範圍縮小後比較圖自動改為下一層
- 兩段式資料匯入｜上傳預覽驗證矩陣、重複檔案偵測、Loc ID 對照、整批寫入或整批不寫入、即時匯入進度
- 單據詳情與來源追溯｜每一筆 SO/DN/WO 都可查看版本歷史與原始 Excel 列的逐欄原始值
- 修正與作廢｜重新上傳自動產生新版本；整批誤傳可作廢，但原始紀錄永不刪除
- 共用匯率設定｜全站共用的報表幣別與各幣別匯率，含版本衝突保護
- 帳號與權限｜管理者／一般使用者角色，可依國家、公司、據點三層授權查看範圍

## AI 的應用方式
- 整個平台由數位發展部以 Claude Code 進行 AI 輔助開發，從資料模型、Excel 解析、匯入流程到儀表板 UI 均由 AI 協作完成
- 以 AI 協助撰寫與維護架構文件（ARCHITECTURE.md）、進行安全性審查（如上傳檔名清理）與 UI/UX 規格改版
- 平台上的「本期重點」刻意採用規則產生，而非 AI 推測文字，確保管理層看到的每句摘要都有真實數據依據

## 使用工具
- Claude Code｜AI 輔助開發、除錯、安全審查與文件撰寫
- React Router 8 + React 19｜SSR 前端框架，建構各分析頁面
- Cloudflare Workers｜網站執行環境與部署
- Cloudflare D1 + Drizzle ORM｜儲存明細、版本、權限與匯率資料
- Cloudflare R2｜永久保存上傳的原始 Excel，供追溯查核
- SheetJS（xlsx）｜在伺服器端解析 SO/DN/WO Excel
- ECharts｜趨勢圖、環圈圖、長條圖等儀表板圖表
- Tailwind CSS + lucide-react｜UI 樣式與圖示
- GitHub Actions｜每日自動備份資料庫

- 建立從上傳、驗證、去重、版本管理到作廢的完整資料匯入管線，每一筆數字都可追溯到原始 Excel 列
- 完成總覽、接單與出貨、工單生產、同期比較、區域／公司／據點分析、單據詳情等頁面

## 產生價值
- 對東南亞總部｜不必再等各單位人工彙整報表，可即時依國家、公司、據點查看接單、出貨與生產狀況，並與去年同期比較
- 對各子公司｜只要上傳 ERP 原始匯出檔即可，不需另做報表格式；重新匯出修正後的檔案系統會自動更新版本
- 對公司｜建立東南亞營運資料的單一可信來源，數字可追溯、可稽核，降低人工彙整造成的誤差與重複計算

## 可複製與延伸應用
- 同一套「兩段式匯入 + Line Rec Key 版本管理 + 原始列追溯」架構，可複製到台灣、大陸等其他地區的 ERP 報表分析
- 可延伸納入更多 ERP 報表類型（如庫存、採購、應收帳款），擴大為區域營運總覽
- 未來可在真實數據基礎上加入 AI 分析摘要或異常偵測，但仍保留數字可追溯的原則

## 使用限制與注意事項
- 資料來源仰賴各單位定期從 ERP 匯出並上傳 Excel，尚未與 ERP 直接串接，資料即時性取決於上傳頻率
- 上傳檔案中的 Loc ID 必須已登記在據點表，否則整批會被擋下，新增據點需先由管理者登記
- SO 匯出檔沒有幣別欄位，金額換算依國家本位幣設定與共用匯率，匯率需由使用者自行維護
- 資料上傳與作廢批次僅限管理者操作；只有公司／據點授權、沒有整國授權的帳號，看不到全區彙總數字

## 成功關鍵
堅持「畫面上每一個數字都來自實際匯入的真實資料」：以 Line Rec Key 做身分識別避免重複計算、全部驗證通過才整批寫入、原始 Excel 永久保存並可逐列追溯，缺資料時誠實顯示而不補值，讓管理層可以放心依據平台數字做決策。
