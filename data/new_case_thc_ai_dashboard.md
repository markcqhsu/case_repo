## 案例標題
集團 AI 推廣管理 Dashboard（THC AI Enablement Platform）

## 案例摘要
建立集團層級的 AI 推廣管理平台，統一追蹤各單位 AI 導入的成熟度（L0～L5）、AI 專案與案例進度、AI 人才盤點、API 使用成本，讓推動 AI 的單位與管理層能在同一個地方掌握全集團的 AI 推動狀況，而不必分散在各單位的報表與口頭回報中，長期目標是發展成集團的 AI Operating System（AIOS）。

## 問題背景
集團各單位陸續推動 AI 應用，但這些進度分散在不同單位、不同格式的報表與會議紀錄中，管理層難以即時掌握全集團的 AI 推動全貌：哪些單位已經導入、導入到什麼程度、有哪些專案與案例正在進行、AI 相關人才配置狀況如何、API 使用成本花費多少，都需要額外彙整才能回答。

## 核心問題
如何用一個統一的平台，讓集團管理層與各單位可以即時查看 AI 推動的成熟度、專案與案例進度、人才配置與 API 成本，取代分散、人工彙整的回報方式。

## 解決方案
建立以 Next.js + Supabase 開發、部署於 Vercel 的 Dashboard 平台，將 AI 推動狀況拆成五個成熟度等級（L0 未啟動～L5 可複製），並整合以下管理模組：
- AI 推動管理：Dashboard 總覽、單位管理、AI 專案管理、AI 案例管理、需求管理
- AI 資源管理：AI 人才管理、API 成本管理
- 系統管理：部門管理、使用者管理（採白名單機制，不開放公開註冊）

首頁 Dashboard 提供 AI 成熟度平均、專案與案例總數、導入單位數、本月 API 花費等關鍵指標，並以圓餅圖與長條圖呈現整體與各地區的成熟度分布，讓使用者可依月份、地區篩選查看。

## 執行流程
- 盤點集團各單位 AI 推動現況，定義 L0～L5 的 AI 成熟度分級標準
- 設計資料庫 Schema 與 RBAC 權限模型（Admin／Viewer 角色搭配 Row Level Security）
- 開發 Dashboard 首頁與各功能模組（單位管理、AI 專案管理、AI 案例管理、AI 人才管理、API 成本管理）
- 部署至 Vercel，串接 Supabase 作為後端資料庫與身份驗證服務
- 後續依各單位回饋持續擴充功能模組（如 Prompt Library、AI Agent Marketplace）

## 主要功能
- AI 推動 Dashboard｜總覽 AI 成熟度平均、專案／案例總數、導入單位數、本月 API 花費，並可依月份與地區篩選
- AI 成熟度分布｜以圓餅圖呈現全集團 L0～L5 各等級單位數與佔比
- 各地區成熟度分布｜以長條圖呈現台灣、大陸總部、東南亞總部及各據點的 AI 成熟度落差
- 單位管理｜維護集團各單位基本資料，作為 AI 推動追蹤的基礎單位
- AI 專案管理、AI 案例管理｜追蹤集團 AI 專案與案例的進度與內容
- AI 人才管理｜盤點集團 AI 相關人才配置
- API 成本管理｜追蹤各單位 API 使用花費與趨勢
- 使用者與部門管理｜白名單登入機制，權限落地在資料庫層（RLS）

## AI 的應用方式
- 平台本身作為集團推動 AI（含本案例庫）的管理工具，用來追蹤各單位 AI 導入的成熟度與進度
- 透過標準化的成熟度分級（L0～L5），將原本質性、口頭回報的 AI 推動狀況量化、視覺化

## 使用工具
- Next.js（App Router）｜前端框架，建構 Dashboard 各頁面
- TypeScript｜前端與後端邏輯開發
- Tailwind CSS + shadcn/ui｜UI 元件與樣式系統
- Supabase｜PostgreSQL 資料庫、身份驗證（Email+Password）與 Row Level Security 權限控管
- Vercel｜前端部署與 Route Handler 託管

## 執行成果
- 平台已上線並可存取（https://thcai.vercel.app/），首頁 Dashboard 可查看集團 AI 成熟度、專案案例總數與導入單位數
- 建立集團 AI 推動的統一資料來源，取代原本分散於各單位的報表與口頭回報
- 完成資料庫 Schema、RBAC 權限設計與核心功能模組開發，持續依需求擴充

## 產生價值
- 對數位發展部｜可即時掌握全集團 AI 推動進度，不需再逐一向各單位收集回報，提升治理效率
- 對集團管理層｜有統一的儀表板了解各地區、各單位的 AI 成熟度落差，作為資源投入與決策依據
- 對各推動單位｜AI 專案與案例被集中記錄與展示，更容易被看見、被複製到其他單位

## 可複製與延伸應用
- 擴充 Prompt Library、AI Agent Marketplace 等模組，讓平台從「追蹤管理」進一步成為「AI 能力共享」的入口
- 串接各單位既有系統（如本案例庫網站）自動匯入案例與專案資料，減少手動輸入
- 依集團 AIOS 長期目標，逐步整合更多 AI 治理與知識管理功能

## 使用限制與注意事項
- 目前仍在開發階段，部分模組（如 API 成本自動歸集）尚待與各單位實際使用資料串接
- 帳號採白名單機制建立，不開放公開註冊或社群登入，需管理者手動邀請
- 成熟度分級與各項數據需仰賴各單位確實填報，資料正確性仍須管理單位定期覆核

## 成功關鍵
以資料庫層級的權限控管（RBAC + RLS）取代單純前端隱藏 UI，確保集團層級的敏感資料在多單位共用平台時仍具備適當的存取控制。
